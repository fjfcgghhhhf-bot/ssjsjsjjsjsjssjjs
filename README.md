# Paper // Code

**Играть онлайн: [paper-code-arena.onrender.com](https://paper-code-arena.onrender.com/).**

Рабочая многопользовательская игра с механикой Paper.io и коллекционированием кодов **876, 156, 367, 986**. Исходный репозиторий `fjfcgghhhhf-bot/ssjsjsjjsjsjssjjs` был пустым, поэтому проект реализован с нуля. Графика, название и интерфейс собственные, без ресурсов Paper.io.

## Быстрый запуск

Нужен Node.js **22 или новее** и npm. В папке проекта:

```sh
npm install
npm start
```

Откройте **http://localhost:3000** в четырёх независимых вкладках или браузерах, задайте имена и нажмите «Войти в лобби». После входа четырёх человек начнётся отсчёт 3 секунды, затем общий раунд с двумя ботами. Зрители и боты не заменяют людей при подсчёте готовности. На компьютере, где установлен только Node.js и уже есть `node_modules`, достаточно `node server.js`.

Tailwind CSS уже скомпилирован в `public/tailwind.css`. Пересобрать после добавления классов:

```sh
npm run build:css
npm test
npm run check
```

Также поддерживается pnpm: `pnpm install`, `pnpm start`. Нативный скрипт необязательного watcher отключён в `pnpm-workspace.yaml`; для однократной сборки CSS он не нужен.

## Архитектура взаимодействия

```mermaid
flowchart LR
  A[Браузер A: Canvas + UI] -->|hello / join / input| WS[WebSocket /ws]
  B[Браузер B: Canvas + UI] -->|hello / join / input| WS
  WS --> R[RoundGame: ожидание 4 человек, отсчёт, раунд]
  R --> G[Game: одна глобальная арена]
  G -->|state + terrain patch, 15 Гц| WS
  G -->|spawn / pickup / capture / death| WS
  WS --> A
  WS --> B
  T[Серверный тик 30 Гц] --> G
```

Сервер хранит клеточную карту **84 × 60**, владельцев клеток, позиции, следы и коллекции. На каждом тике он продвигает квадраты со скоростью 6 клеток/с, рассчитывает столкновения, захват и подбор. Клиент может отправить только направление: координаты, владения и «событие подбора» от клиента не принимаются. Боты проходят ту же симуляцию, что и игроки. Интерфейс тёмный со светло-розовыми акцентами; правая колонка удалена, арена занимает всю ширину, порядок кодов показан компактной полосой над полем.

Клиент получает позиции и следы 15 раз в секунду. Снимки воспроизводятся с буфером **100 мс**, который сглаживает неравномерное поступление пакетов. Приём нового пакета не перезапускает анимацию. Сервер передаёт время прохождения центров клеток: движение проходит через каждый угол, без диагональных срезов. Голова, непрерывная лента хвоста, камера, миникарта и территория используют одну временную шкалу; будущие клетки хвоста не рисуются впереди головы. При потере пакетов анимация останавливается на последнем подтверждённом состоянии, не придумывая движение. История ограничена 32 снимками, чтобы фоновые вкладки не копили данные бесконечно.

Изменения территории передаются парами `[индекс, владелец]` и применяются по мере воспроизведения соответствующего снимка. При входе, восстановлении и каждые 5 секунд передаётся полная карта. WebSocket сохраняет порядок сообщений. Если клиент не успевает принимать данные, соединение закрывается, затем он получает полное состояние после переподключения. По умолчанию на арене **два бота**, которые соблюдают те же правила, что и игроки.

### Захват и столкновения

1. Выйдя со своей территории, квадрат оставляет незащищённый след.
2. При возвращении сервер временно объединяет базу и след в непроходимую границу.
3. Заливка идёт от всех краёв карты. Недоступные извне клетки составляют замкнутую внутреннюю область. Она и след переходят игроку, включая чужую территорию.
4. Пересечение своего следа или края карты убивает игрока. Пересечение следа соперника убивает владельца следа.
5. При одновременном столкновении голов на нейтральном поле погибают оба. На собственной территории её хозяин побеждает. Проверяется также обмен соседними клетками за один тик.
6. Игрок, находившийся вне собственной базы, погибает, если чужой захват накрывает его голову. Потеря всей территории также заканчивает раунд.
7. После смерти освобождаются все клетки и след. Коллекция сохраняется при возрождении внутри текущего общего раунда и очищается перед следующим. Новый игрок получает 2 секунды защиты от соперников; край карты и собственный след по-прежнему опасны.

Команды поворота имеют возрастающий номер `seq`. Старые, некорректные и обратные команды отклоняются. До двух поворотов можно поставить в очередь. Поворот выполняется после прибытия к центру очередной клетки.

### Общий раунд и очередь кодов

`RoundGame` расширяет симуляцию `Game` и управляет четырьмя состояниями:

1. **waiting** — персонажи и боты стоят, кодов на карте нет. Считаются только подключённые человеческие сессии, нажавшие «Войти в лобби».
2. **countdown** — при четырёх людях начинается серверный отсчёт 3 секунды. Выход или обрыв соединения до старта отменяет отсчёт. Два бота и зрители не входят в порог.
3. **playing** — карта сбрасывается, все участники начинают вместе. Появляется только `876`. Затем коды идут строго в порядке **876 → 156 → 367 → 986**: следующий появляется через 7 секунд после подбора предыдущего. Подобранный код в этом раунде больше не возвращается. Неподобранный код через 40 секунд перемещается в другую точку; очередь при этом не продвигается. Всем приходят уведомления о спавне и подборе.
4. **finished** — когда участники суммарно собрали все четыре кода, движение и спавн прекращаются. Результаты показывают, кто забрал каждый код. Через 8 секунд все оставшиеся подключённые участники возвращаются в лобби; карта, коллекции и счёт сбрасываются. Если людей снова достаточно, начинается новый отсчёт.

Во время раунда разрешены поздний вход и повторный старт после гибели. Уменьшение числа людей ниже четырёх после старта не отменяет уже начавшуюся охоту; если не осталось ни одного подключённого человека, арена возвращается в тихое лобби. Идентификаторы оставшихся игроков сохраняются между общими раундами, чтобы переподключение продолжало работать. Смена `boardEpoch` сопровождается полной картой и очищением клиентского буфера: перемещение на новые базы не рисуется как скачок через всю карту.

Базовый `Game` также используется отдельно в тестах столкновений и таймеров. В HTTP/WebSocket-сервере всегда создаётся `RoundGame`, который управляет спавном только внутри раунда.

### Протокол WebSocket

Каждое сообщение — JSON с полем `type`.

| Направление | Сообщение | Назначение |
| --- | --- | --- |
| Клиент → сервер | `hello { token? }` | подключение или продолжение сессии |
| Клиент → сервер | `join { name, color }` | новый раунд; `color` — индекс 0…5 |
| Клиент → сервер | `input { dir, seq }` | `up`, `down`, `left`, `right` |
| Клиент → сервер | `ping { nonce }` | измерение задержки |
| Клиент → сервер | `sync` | запрос полного состояния |
| Клиент → сервер | `leave` | выход и освобождение территории |
| Сервер → клиент | `hello { token, selfId, collection }` | непрозрачный токен текущей сессии |
| Сервер → клиент | `joined { selfId, collection }` | подтверждение начала раунда |
| Сервер → клиент | `state { time, revision, players, codes, match, grid?, patch? }` | авторитетный снимок мира |
| Сервер → клиент | `events { events[] }` | спавн, подбор, захват, смерть |
| Сервер → клиент | `pong`, `left`, `error` | служебные ответы |

`match` содержит фазу, номер раунда, число готовых людей, участников лобби, временные метки отсчёта/следующего кода/возврата и список найденных кодов. События `round-countdown`, `countdown-cancelled`, `round-start`, `round-finished` и `lobby-open` дополняют игровые уведомления.

Токен сохраняется в **sessionStorage**: независимые вкладки получают независимых игроков, перезагрузка страницы восстанавливает текущую сессию. После обрыва соединения клиент повторяет подключение с задержкой 1…10 секунд. Сервер держит сессию 30 секунд; движение в общем мире продолжается, поэтому игрок может погибнуть во время обрыва. По истечении 30 секунд владения и сессия удаляются.

## Управление

- Стрелки, WASD и соответствующие клавиши русской раскладки.
- Свайпы и экранные кнопки на сенсорном устройстве.
- Щелчок по карте задаёт направление относительно центра экрана.
- Кнопка звука включает короткие сигналы подбора, захвата и смерти.
- Полный экран, окно правил, выход из раунда и повторный старт работают в интерфейсе.

## Настройки и публикация

Переменные среды указаны в `.env.example`. `.env` можно загрузить командой `node --env-file=.env server.js`; обычный `npm start` читает переменные процесса, а не файл автоматически.

| Переменная | По умолчанию | Описание |
| --- | --- | --- |
| `PORT` | `3000` | порт HTTP и WebSocket |
| `HOST` | `0.0.0.0` | сетевой интерфейс |
| `BOT_COUNT` | `2` | поставить `0`, чтобы играть только с людьми |
| `MAX_PLAYERS` | `48` | лимит живых игроков, включая ботов |
| `MAX_CONNECTIONS` | `128` | лимит WebSocket-соединений |
| `CODE_TTL_MS` | `40000` | время до смены точки |
| `CODE_RESPAWN_MS` | `7000` | задержка перед следующим кодом |
| `PUBLIC_ORIGIN` | не задан | точный HTTPS-origin за reverse proxy |

Для доступа игроков из интернета разместите **один экземпляр** этого Node.js-сервера на VPS или хостинге с длительными WebSocket-соединениями. Все подключаются по одному публичному URL — это и есть глобальное лобби. Несколько независимых экземпляров создадут разные арены; Redis-адаптер сам по себе не объединит симуляции. Для горизонтального масштабирования нужен отдельно выделенный единственный владелец симуляции и шлюзы сети.

Docker:

```sh
docker build -t papercode .
docker run --rm -p 3000:3000 -e BOT_COUNT=2 papercode
```

За HTTPS-прокси задайте `PUBLIC_ORIGIN=https://your-domain.example` и передавайте WebSocket Upgrade. Пример блока Nginx:

```nginx
location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_read_timeout 60s;
}
```

Состояние арены и коллекций хранится в памяти и сбрасывается при перезапуске сервера. Постоянные аккаунты, база данных и долговременная коллекция не входят в эту версию. `GET /health` возвращает состояние сервера для мониторинга.

### Render

`render.yaml` описывает один Docker Web Service на тарифе Free во Frankfurt, с двумя ботами, проверкой `/health` и автоматическим обновлением из `main`. Файл можно использовать как Blueprint; при ручном создании Web Service выберите тот же репозиторий, Docker, Frankfurt и Free, задайте `BOT_COUNT=2` и Health Check Path `/health`. Docker запускает `node server.js`, Render задаёт `PORT`, сервер слушает `0.0.0.0`.

Клиент автоматически использует `wss://` на HTTPS-адресе сервиса; отдельный домен для WebSocket не нужен. Оставьте один экземпляр: память нескольких экземпляров не образует общую арену.

На [бесплатном тарифе Render](https://render.com/docs/free) сервис засыпает после 15 минут отсутствия входящего трафика. Первое открытие после сна требует времени на запуск. При перезапуске игровая карта и коллекции сбрасываются.

## Проверка

Тесты используют встроенный `node:test`: проверяют заполнение внутренней области, незамкнутые линии, самопересечение, хвосты, стену, одновременные столкновения, захват уязвимого соперника, тайм-ауты, респавн и единственность подбора. Дополнительно проверяются две минуты игровой симуляции ботов, воспроизведение карты из патчей, реальные WebSocket-клиенты в одном лобби, общая рассылка событий, восстановление сессии, запрет дублирования активного токена, HTTP-маршруты и проверка Origin. Отдельные регрессионные тесты воспроизводят частые и неравномерные пакеты, проверяют постоянную скорость без откатов, точные углы поворотов, синхронное начало и очистку хвоста, сетевую паузу, повторный полный снимок и перезапуск сервера. Запуск по умолчанию проверяется на наличие ровно двух ботов без кодов. Тесты `RoundGame` проверяют ожидание, отмену отсчёта, последовательный спавн, завершение после четвёртого кода, очистку коллекций и возврат в лобби. Интеграционный тест с четырьмя реальными WebSocket-клиентами проверяет, что зрители и боты не запускают раунд, а отключение и восстановление готового участника корректно меняют отсчёт.

Технические источники: [WebSocket-библиотека ws](https://github.com/websockets/ws), [локальная сборка Tailwind CSS](https://tailwindcss.com/docs/installation/tailwind-cli). Игровой референс: [Paper.io 2](https://paperio.site/).
